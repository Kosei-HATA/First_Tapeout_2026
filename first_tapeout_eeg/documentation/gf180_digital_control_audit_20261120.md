## 1. 第 1 回（11/20 0 時〜）の指摘と対応

### 1.1 重大

1. **WARMUP の反映のすぐあとに AFE_RST を解除しうる。**
   - 指摘：WARMUP の APPLY と APPLY_NR は T_WARM を数え直さない。このため、オフセット DAC の変更と同じ tick（またはすぐあと）に AFE_RST を解除しうる。これは 11/16 の飽和の評価の結論（DAC の変更のあとは必ず AFE_RST を経る）に反する。
   - 確かめ：状態遷移表と RTL を読んで確かめた（自ら発見）。性質の検査は tick ごとであり、反映と解除の関係を持っていなかった。
   - 対応：
     - WARMUP での反映に動作 restart を加え、T_WARM を最初から数え直す。同じ tick の満了は取り消す（仕様源と RTL）。
     - 性質を 2 件追加した。解除の tick に反映しないこと。AFE_RST を保つ間の反映は待ちを数え直すこと。
     - 要件 SEQ-16 を新設した。
   - 検証：
     - 自己試験（APPLY と APPLY_NR）。
     - tb_seq のタイマの独立の模擬（再読み込み 6,899 回）。
     - tb_top_r14 J4：変更から解除まで 5,000.0 µs。
2. **サンプルの OVL が、sinc³ の窓 3 ms のうち直前の 1 ms しか見ない。**
   - 指摘：最も壊れたサンプル（過負荷を窓の中ほどに含むもの）が、OVL ＝ 0 で出る。
   - 確かめ：監査の模擬で確かめられた。過負荷のあとの 3 個のうち 2 個目の誤差が最大（＋226,006）で、OVL ＝ 0 であった。
   - 対応：OVL を、この出力と直前の 2 個の出力の間隔のいずれかでの検出とした。記録は 2 ビットである。検出の遅れ（最大 4 フレーム）は、窓の新しい端の重み（1e−8 未満）から影響しない。
   - 検証：tb_top_r14 J7。約 40 µs の過負荷で、OVL はちょうど 3 個のサンプルに立ち、前後には立たない。
3. **SOFT_RESET が、そのチップだけの格子・SEQ・CHOP1 を戻す。**
   - 指摘：MCLK と RESET_N を共有するチップの間で、同じ SEQ が同じ時刻という約束（SEQ-07、DAT-03）が黙って崩れる。
   - 確かめ：監査の 2 チップの模擬で確かめられた。341 µs のずれと、SEQ の不一致が出た。
   - 対応：
     - SOFT_RESET は制御（レジスタ、シーケンサ、SPI、FIFO、フラグ、CHANGED、DRDY_N）だけを戻すこととした。
     - 時刻とデータの経路（フレームとチョッパ、CHOP1、CIC、過負荷の検出、SEQ、RAW、eeg_adc_dig）は RESET_N から続ける。
     - 要件 RST-02 と SEQ-07 を改訂した。
   - 検証：tb_top_r14 H。フレームの計数が MCLK の数どおりに続き、SEQ も戻らない。
4. **模範のホスト手順が書かれたとおりには動かない。**
   - 指摘：
     - READY は命令の実行を示さない。命令は次の tick まで未処理であり、拒否（CFG_ERR）でも READY は 1 のままである。
     - APPLY のあとに、古い設定のサンプルが FIFO に残る。
   - 確かめ：監査の模擬で確かめられた。APPLY の直後の STATUS は READY ＝ 1、CMD_PENDING ＝ 1 であった。RUN に戻ったあとの最初のサンプルは、APPLY の前のものであった。
   - 対応：
     - APPLY（パルスあり）で FIFO を空にする（START と同じく、データの区切り）。
     - 手順を改訂した。全ての命令で、CMD_PENDING ＝ 0 を待ってから ERR を確かめる。
   - 検証：tb_top_r14 J5（APPLY の tick で FIFO が 0）、J2（CMD_PENDING）、tb_seq。

### 1.2 中

5. **64 kHz で、未処理の命令の間に書いたシャドウを、その命令が読む。**
   - 指摘：64 kHz では書き込みのフレーム（8 µs）が tick の間隔（15.6 µs）より短い。このため、M_H だけ新しく M_L は古い、といった値を APPLY が写しうる。
   - 対応：未処理の命令がある間は、シャドウ（一括反映の対象）とタイマへの書き込みを STATE_ERR として書かないこととした。対象のアドレスは regmap.py の GUARDED_ADDRS として生成し、条件 busy を拡張した。
   - 検証：tb_top_r14 J2（シャドウとタイマは書かれない。守らないレジスタは書かれる）、tb_spi_r14 の照合。
6. **高抵抗の電極では、APPLY_NR の 1 段の整定が CHANGED の 3 個を超える。RUN の前には待ちがない。**
   - 指摘：電極の R_e C_e（51 kΩ ∥ 47 nF で 2.4 ms）のため、1 段のあと約 12 ms の間、残りの整定が CHANGED なしで出る。
   - 対応：
     - CHANGED を 3 ＋ T_ELEC 個とした。T_ELEC は電極の整定の時間で、ホストが設定する。
     - RUN の前の 1 段では、T_ELEC ＞ 0 なら電極の整定を待ち直す。WAIT_E では数え直し、ALIGN と FILL からは WAIT_E へ移る。
   - 検証：自己試験 3 種、tb_seq（77 欄）、tb_top_r14 D（T_ELEC ＝ 2 で CHANGED 5 個）、D2（第 19 項）。
7. **オフセットの探索が、点ごとに T_ELEC を待つ（問題点 C8 の再発）。**
   - 対応：探索の間は T_ELEC ＝ 0 とし、決めた M で戻すよう手順に明記した。

### 1.3 軽

8. **先頭バイトの R/W の 1 ビットの化けで、読み出しが書き込みとして確定しうる。**
   - 指摘：CRC 無効では、読み出しの空のバイトが書き込まれる。
   - 対応：
     - 読み出しの先頭バイト以降の MOSI を 0x00 と規定した。CRC 有効なら CRC_ERR か ADDR_ERR となり、黙っては書かれない。
     - 書き込みの MISO が 0x00 であることを確かめる手順を加えた（書き込みが読み出しに化けた場合の検出）。
9. **フレームの種類の化け（読み出しとサンプル）を、CRC が 1/256 で見逃す。**
   - 対応：CRC 有効時は、CRC のバイトのない読み出しと、8 バイトでないサンプルを FRAME_ERR とした（先頭バイトだけの読み出し、すなわち STATUS の確認は正当のまま）。
   - 検証：SPI のフレームの検査（3,520 通り）、tb_top_r14 J3。
10. **SOFT_RESET と RESET_N の解除の直後の、SPI の時間の条件が未規定。**
    - 指摘：最小の条件では、SOFT_RESET の直後のフレームが先頭のビットを失う（監査の模擬）。
    - 対応：SOFT_RESET のあとは CS_N の High を 1 µs 以上とし、RESET_N の Low の間と解除から 10 MCLK は CS_N を High とすると規定した。
11. **SCLK の Low の最小（4 MCLK）と MISO の遅れ（最大 3 MCLK ＋ 15 ns）の余裕が 15 ns しかない。**
    - 対応：Low を 5 MCLK 以上とした。
12. **DRDY_N が設定で選ぶ組み合わせ出力であった（NFR-06）。レベルの設定で High に戻る遅れも未規定。**
    - 対応：DRDY_N を 1 個のレジスタの出力とし、遅れ（最大 5 MCLK）を規定した。
13. **8 バイトのサンプルの MISO の化けで、そのサンプルを失う。**
    - 対応：CS_N を上げる前に SCLK を 1 回余分に入れれば、取り出されずに読み直せることを規定した（FRAME_ERR となる）。
14. **検査器の主張が、実際の検査より広い。**
    - 指摘：
      - SPI のバイト数とエラーの欠落の 6 種は、検出されなかった。
      - タイマの丸めが浮動小数で、危険側に 1 tick 長い。
      - 満了の「必ず」は、全ての分岐が留まる場合だけを見ていた。
    - 対応：
      - SPI のフレームを、表とは独立に書いた意味の定義（spi_expect）と照合することとした。3 種 × CRC × 条件の全ての値 × 0〜10 バイトと途中のビットで、3,520 通りである。
      - タイマの丸めを整数のフレームで行い、満了は全ての分岐を見ることとした。
      - 語彙の検査（未使用の動作と条件）を加えた。
      - 自己試験は 50 種に増え、全て検出した（32 種から増加）。
15. **試験の穴。**
    - 指摘：
      - STATUS の CMD_PENDING、DATA、OVL_NOW、AFE_RST の固着を、試験が検出しない。
      - OVL の経路、SEQ の折り返し、FIFO の 4 段を、どの試験も通らない。
    - 対応：tb_top_r14 に J（STATUS の全ビット、守るレジスタ、CRC のフレーム、WARMUP、APPLY の空化、過負荷）と K（SEQ の 0xFFFF から 0 への折り返し）を加えた。FIFO 4 段での実行も加えた（run_tests_r14.sh）。

### 1.4 文書と仕様源の不一致

16. 次の不一致を修正した。
    - 未使用の動作 cancel（r2 の名残）。
    - FILL と RUN の出力の時刻で、満杯の扱いが異なっていた（満杯の判断は FIFO の規則に一本化）。
    - 存在しない ALERT_N。
    - FLG-01（STATUS に状態はない）、FLG-02（OVERRUN と OVL は DFLAG にある）。
    - R-04 と R-11 の旧い規則。
    - SEQ-05 と TIMING のタイマの範囲（T_RST の最大は 1.99 ms）。
    - IDLE の STOP の扱い（受け付けて何もしない）。
    - §2.1 の写しの説明（端子の値と異なる 2 点）。
    - 空の語の他のビット。
    - SEQ と連続読み出しの折り返し。
    - CS_N の共有の禁止（全てのフレームで STATUS を返すため）。
    - DFLAG のクリア。
    - ERR の W1C では、読んだ値を書き戻すこと。

### 1.5 検証の穴（自ら）

17. **シーケンサの照合（VER-09）が、タイマの値を確かめていなかった。**
    - 指摘：RTL の満了の旗をそのまま事象として使っていた。
    - 対応：tb_seq がタイマの値（事象の前後）、フレームの数、タイマの設定を記録し、照合器が全ての読み込み・減算・数え直しを独立に模擬するようにした。
    - 検証：変異の自己試験で、1 フレームの差、単位の誤り、数え直しの欠落を全て検出した。

### 1.6 アナログの未確認事項（デジタルの仕様の誤りではない）

18. **IDLE（STOP のあと）と WARMUP も、AFE_RST ＝ 1 でチョッパが動いている。**
    - 指摘：電極から見て約 5.4 kΩ の負荷である（`gf180_realistic_eval_20261028.md`）。STOP は低電流の待機ではない。
    - 対応：手順と未確認事項に記録した。チョッパを止めた AFE_RST の電極の負荷は、アナログの評価を要する。

### 1.7 追加（第 1 回の確定前、自ら）

19. **RUN を出ても、CHANGED の残りが次の RUN のサンプルに付く。**
    - 指摘：CHANGED の計数は RUN の外でも出力ごとに減るだけで、消えない。T_ELEC の長い APPLY_NR のあとに APPLY や STOP と START を行うと、クリアした CIC から始まる次の RUN の最初のサンプルにも CHANGED が付き、正しいサンプルを捨てさせる。
    - 確かめ：RTL を読んで確かめた（自ら発見）。T_ELEC ＝ 30 の印（33 個）は、APPLY の経路（約 4.4 ms）のあとも約 26 個残る。
    - 対応：RUN 以外の状態では計数を 0 とした（印は RUN の中でのみ付く。サンプルは RUN でのみ格納する）。要件 SEQ-06、DAT-02、仕様源の動作 mark とサンプルの状態の CHANGED に明記した。
    - 検証：tb_top_r14 D2（T_ELEC ＝ 30 の印のあとの APPLY で、次の RUN のサンプル 3 個に CHANGED なし）。変異の自己試験に「RUN を出ても CHANGED の残りを消さない」を加えた。

### 1.8 試験の不備（自ら）

20. **変異によっては、試験が終わらずに待ち続ける。**
    - 指摘：一括反映の漏れ（CPF_TRIM を写さない）の変異で、J4 の CPF_TRIM の変化の待ちが終わらず、変異の実行が 17 分以上止まった（誤りは C で検出済み）。
    - 対応：J4 の待ちに上限（100 µs）を設けた。試験全体に監視（模擬時間 250 ms、通常の約 2 倍）を加え、超えれば段の名前とともに FAIL で終える。変異の実行器も、時間切れを検出として扱う。
    - 変異の文言の追従：第 1 回の修正で RTL の文言が変わった変異 3 種（バイトの途中の CS_N、CHANGED の数）を、新しい文言に合わせた。
