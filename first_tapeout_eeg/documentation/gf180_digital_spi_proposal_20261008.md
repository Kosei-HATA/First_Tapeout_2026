# GF180 ADCを外部MCUへ接続するデジタル回路案

> **10/22 追記**：今回の rev では数値を次のとおり改める。それ以外のコマンド、フレーム、レジスタの考え方はこの案を基にしている。
> - ADC クロック：1.024 MHz（MCLK 32.768 MHz の 32 分周）
> - CIC：R=1024、W=37、SHIFT=12、出力 1 kSPS
> - 量子化器：5 bit 固定
> - 実装：`gf180/tapeout/rtl/`、全体の状況：`gf180_tapeout_tracker.md`

2026-10-08。接続先は外部MCU（型番未定）。まず1チャネル、5/6bit量子化器・512 kHzのADCを対象に、**チップ内CIC → 小容量FIFO → SPI**を基本構成とする。最終的なEEG帯域のフィルタやEOG推定はMCU側に置く。

本書は設計案であり、新しいRTLの実装・合成・アナログ接続検証はまだ行っていない。既存の回路・インターフェース要件・週報は変更していない。

## 推奨する最小構成

```mermaid
flowchart LR
    A[AFE・ADC比較器] --> Q[出力ラッチ・コード化]
    Q --> D[帰還DAC制御]
    D --> A
    Q --> C[CICフィルタ<br/>512 kHz → 1 kSPS]
    C --> F[8サンプルFIFO]
    F --> S[SPI・設定レジスタ]
    S <--> M[外部MCU<br/>最終フィルタ・記録]
    X[独立した基準クロック] --> T[位相・チョッパ制御]
    T --> A
    T --> Q
```

| 項目 | 初期案 |
| --- | --- |
| 通信 | 4線SPI、チップ側がスレーブ、Mode 0、MSB first |
| 読み出し | 符号付き24bit、1 kSPS、1サンプル8バイト |
| SPI速度 | 通常1 MHz、上限設計目標2 MHz。保証値は実装・パッド込みで確認 |
| バッファ | 8サンプル。データ24bit＋連番16bit＋状態8bitを保持 |
| 通知 | `DRDY_N`：FIFOにデータがあればLowを維持 |
| ADCクロック | SPIとは独立。外部32.768 MHzを候補とし、64分周で512 kHz |
| 外部デジタル信号 | `SCLK / CS_N / MOSI / MISO / DRDY_N / MCLK / RESET_N`の7本 |
| 電圧 | 3.3 V系を候補。採用パッドとMCUのI/O条件を合わせる |

電源・GND・アナログ入力・基準電圧の端子は上記7本に含まない。32.768 MHzは位相生成のための候補値で、MCUから生成できるとは仮定しない。基板上の発振器、または条件を満たすMCUクロック出力から常時供給する。

## ADC側で必要な制御

現在の多ビットSPICEには理想電源や振る舞いモデルによる制御が含まれる。SPIを追加するだけでは実装できず、次のデジタル処理が必要になる。

- **比較器出力の保持とコード化**：31本／63本のサーモメータ出力を決まった時刻に保持し、1の個数を5bit／6bitコードに変換する。5/6bitは回路生成時のパラメータとし、初版の動作中切替は設けない。
- **帰還DACの選択制御**：現在のDWAなし回路では、コードを`c`、素子数を`N=2^B−1`とすると、P側のVP選択数は`N−c`、N側は相補となる。第1段は同周期のPH2、第2段は保持したコードで次のPH1を駆動する。CICやSPIの遅延を帰還経路へ入れない。
- **位相生成**：PH1、PH2、比較器クロック、チョッパ位相を生成する。出力をレジスタ化し、PH1とPH2が重ならないようにする。
- **起動制御**：デジタルリセット、フィルタ初期化、出力有効化を分ける。デジタルの`RESET_N`だけでアナログ積分器が初期化されるとは扱わず、必要なリセットスイッチはアナログ側との接続要件に含める。

RUN／STOPはアナログ位相の安全な境界で反映し、停止時はPH1・PH2をともに無効にする。コードの符号と電極入力の極性は接続後の応答で確認する。

最初はDWAなしの動作を合わせる。DWAは素子の選択個数と更新時刻を独立に検証してから追加する。基準電圧ラダーや比較器自体はアナログ側の実装範囲である。

32.768 MHzなら1刻み30.52 ns、ADCの1周期を64刻みで表せる。現行PULSE波形に近い出発点として、PH1を0〜26、比較器を20〜25、出力保持を27、DAC1更新を29、PH2を32〜58、DAC2更新を59とする案がある。DAC1更新からPH2までは約91.6 ns。この位相表は**検討用**であり、比較器の判定時間・エンコーダ遅延・スイッチ整定を含めて確認する。

## フィルタは1 kSPSまでをチップ内で処理

乗算器を使わない3段CIC（sinc³、差分遅延1、間引き比512）を候補とする。単純にサンプルを抜くと帯域外成分が折り返すため、間引きとフィルタを組にする。CICの通過帯域の傾きと整定時間も設計に含める。[ADIのデジタルフィルタ解説](https://www.analog.com/en/resources/technical-articles/fundamental-principles-behind-sigma-delta-adc-topology-part2.html)

512 kHz入力について、理想的なsinc³の伝達関数から計算した比較は以下のとおり。

| 出力レート | 間引き比 | 100 Hzでの利得 | フィルタ固有の群遅延 |
| --- | ---: | ---: | ---: |
| 250 SPS | 2048 | −7.26 dB | 6.00 ms |
| 500 SPS | 1024 | −1.74 dB | 3.00 ms |
| **1 kSPS** | **512** | **−0.43 dB** | **1.50 ms** |
| 2 kSPS | 256 | −0.11 dB | 0.75 ms |

初版は1 kSPSでMCUへ送り、必要に応じてMCUで帯域補正と低域フィルタをかけ、500 SPS等へ落とす。1 kHzチョッパを同じ基準から生成すれば、理想CICの零点とも揃う。ただし、チョッパ雑音や量子化雑音の折返しが十分小さいかは実コード列で確認する。MCUの後段フィルタでは、既に帯域内へ折り返した成分を取り除けない。

入力コードは`x=2c−(2^B−1)`として中心化する。5bit量子化器では符号付き6bit、6bitでは7bitが必要になる。CICの利得は`512³=2²⁷`なので、内部幅は共通で**34bit**を確保する。積分器は同じ幅の剰余演算を使い、途中で飽和させない。出力時に5bit版は9bit、6bit版は10bit右へ丸めて24bit化し、変換係数をFORMAT情報とともに定義する。24bitは出力形式であり、24bit ENOBを意味しない。

CIC単体の整定は約3 ms。起動直後の出力を無効にし、AFE・ADCの整定を含む待機時間は別途設定する。ここでの群遅延にはRTLの追加パイプライン・FIFO・通信・MCUフィルタの遅延を含まない。

## SPIとデータ保持の仕様案

1サンプルの読出しを固定8バイトにすると、MCUのSPI＋DMAで扱いやすい。

| バイト位置 | MOSI | MISO |
| --- | --- | --- |
| 0 | `0x30`：READ_SAMPLE | 無視 |
| 1 | ダミー | STATUS |
| 2〜3 | ダミー | 16bit連番、上位から |
| 4〜6 | ダミー | 24bit符号付きデータ、上位から |
| 7 | ダミー | CRC-8 |

CRCはSTATUSからデータ末尾までの6バイトを対象に、poly=`0x07`、init=`0x00`、反転なし、xorout=`0x00`とする。通常運転は64 bit×1,000回/秒＝64 kbit/s。SPI 1 MHzなら1回64 µs、転送部分の占有率は6.4%となる。

- FIFO先頭をコマンド受信時に読み出し用レジスタへ保持し、通信途中で新しいサンプルに変わらないようにする。
- CS_Nを下げて1トランザクション、上げて終了。8バイト完了後のCS_N解除で1サンプルだけ消費する。途中終了・余分なクロックでは消費せず、再読出し可能にする。最初は連続バーストを設けない。
- FIFOが空ならSTATUSのVALID=0、データ=0として返す。FIFOが満杯なら新しいサンプルを捨て、OVERRUNを記録する。古いデータを上書きしない。
- 連番は有効な出力サンプルを生成するたびに進め、FIFOあふれによる欠落をMCU側で検出できるようにする。16bit連番は1 kSPSで65.536秒ごとに周回する。
- 8サンプル分の蓄積時間は8 ms。MCUは通常1 msごと、遅くとも余裕を持ってFIFOを空にする。DRDY_Nは一瞬のパルスではなく、データが残る間Lowを維持する。

設定は3バイトの`READ_REG(0x10), address, dummy`または`WRITE_REG(0x20), address, value`で行う。READの応答値は3バイト目。WRITEは全バイト受信後のCS_N解除で確定し、読戻しで確認する。

| レジスタ | 内容 |
| --- | --- |
| `0x00 ID` / `0x01 VERSION` | 接続確認と実装版の識別 |
| `0x02 CONTROL` | RUN／STOP、停止中のFILTER_CLEAR。電源断機能とは分ける |
| `0x03 STATUS` | FIFO有無、整定中、OVERRUN、コマンドエラー。エラーはW1C |
| `0x04 FORMAT` | 実装した量子化器ビット数・出力スケール・極性の識別 |
| `0x05 FIFO_LEVEL` | 未読サンプル数 |
| `0x06〜0x07 ODR` | 初版では固定1,000 SPSを読み出す |
| `0x10以降` | 将来のゲイン・レート設定用に予約 |

ゲイン設定は、実際に切替可能なAFEの容量バンクと制御端子が揃ってから追加する。現段階で未実装機能をレジスタだけで動作するものとして扱わない。

### クロックをまたぐ処理を小さくする

初版は内部をMCLKの単一クロックに揃え、CIC・FIFOもクロックイネーブルで更新する。非同期のSCLK・CS_N・MOSIは同期化してからSPIのエッジを検出する。32.768 MHzに対してSPI 2 MHzなら約16倍のサンプリング比があり、別クロックの非同期FIFOを省く構成を検討できる。

Mode 0で立上り受信・立下り送信とし、SCLKのHigh/Low時間は各250 ns以上、CS_Nの開始前／終了後の余裕は各1 µs以上を設計条件の候補とする。同期化遅延を含むMISO応答は最大4 MCLK周期（約122 ns）以内を目標にし、残りの時間でパッド・基板・MCUのセットアップを満たすかSTAと位相を変えたRTL試験で確認する。周波数比だけで動作保証とはしない。

CS_N解除とRESET_NでMISOパッドを速やかに高インピーダンスへ戻す。リセットは非同期アサート・MCLK同期解除とする。SPI停止中もADCクロックは継続する一方、MCLK停止中の通信は保証しない。

## デバッグ経路と面積

生コードの連続出力は通常のSPIとは分けて考える。512 kHz×5bitで2.56 Mbit/s、6bitで3.072 Mbit/s、1バイト単位では4.096 Mbit/sとなり、上記2 MHz SPIでは足りない。

評価用には追加2端子の`RAW_DATA / RAW_CLK`で1コード8bitを4.096 MHzで送り出す案を残す。採用する場合は、MCUの別SPIをスレーブ受信＋DMAにできるかを確認する。開始時のフレーム境界と受信準備の手順も必要になる。通常測定では出力を停止し、今回の最小7端子には含めない。

面積は、FIFOの384bit、CIC、コード化、位相生成、SPI、制御を合わせて800〜1,200 FF・2,000〜4,500 NAND2相当を**仮の予算**とした。ローカル9t5v0 LEFのDFFQ=79.03 µm²、NAND2=14.11 µm²、配置利用率50%から、配置領域は約**0.18〜0.32 mm²**となる。これは合成結果ではなく、パッド・アナログDAC・比較器・最終クロック配線・分離領域を含まない。初期フロアプランではデジタル用に0.4 mm²程度を仮置きし、合成後に更新する案とする。Half全体への収容はアナログとパッドを合わせて判断する。

GF180には三状態出力付きI/Oがあり、3.3 V系の特性評価コーナーも公開されている。採用パッドと3.3 V条件の実ライブラリを選び、入力閾値・出力遅延を確認する。クロック線とSPI出力はアナログ入力・基準電圧から離し、帰還DAC制御を含めたスイッチングの影響を確認する。[I/Oセル仕様](https://gf180mcu-pdk.readthedocs.io/en/latest/IPs/IO/gf180mcu_fd_io/datasheet.html)、[評価コーナー](https://gf180mcu-pdk.readthedocs.io/en/latest/IPs/IO/gf180mcu_fd_io/corners.html)

## 既存資産の確認結果と根拠

旧SKY130試作RTLを読み、そのまま利用できるかだけ小規模に確認した。`cic_decimator.sv`は1bit・16 kHz用で、間引きカウンタが7bit固定のためR=512には対応しない。正入力固定の試験では出力16,384となり、コメントにある4,194,304とも一致しなかった。`eeg_clkgen.sv`のclk16は入力32周期で1周期となり、256 kHz入力なら8 kHzになる。これは**旧試作RTLの結果**であり、現在のGF180 SPICEのクロックについての指摘ではない。
