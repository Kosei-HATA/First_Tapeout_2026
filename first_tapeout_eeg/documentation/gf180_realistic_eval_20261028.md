# 実際に近い条件での立ち上がりと性能（管理表 D7、10/27〜）

10/27 に、立ち上がりの図が理想化した条件のもの（解いた動作点から始め、理想のバイアスと電源、共通の理想グラウンド、typical だけ）だったことについて、ユーザーから次の指示があった：「実際にそんな挙動をするかというのが大事」「製造ばらつきなんかも考えると monte-carlo 法とかも含めるべき」「立ち上がりに限らず、性能等の評価でも一緒です」。この文書は、その条件で立ち上がりと性能を測り直した結果をまとめる。チップは 6 回目（r6、10/26）。10/27 夜に組み直した GDS は r6 とマスクが同じ（XOR で全層一致）なので、抽出も同じ。

## テストベンチ

| スクリプト | 何を測るか |
|---|---|
| `gf180/tapeout/pex/afe_startup.py` | AFE の電源投入からの過渡（power：リセットのまま、start：RTL の順序で解除まで） |
| `gf180/tapeout/pex/afe_chip_noise.py` | チップの実際の動作点での AFE の雑音（`pex_afe.py` の noise と同じ方法） |
| `gf180/tapeout/pex/pex_chipnets.py` | チップの配線の抽出（結果と方法は `gf180/tapeout/pex/runs/chipnets/README.md`） |
| `gf180/tapeout/pex/e2e_startup.py` | 電極から ADC の符号までの電源投入からの通し（AFE と ADC はトランジスタのまま） |
| `gf180/tapeout/pex/adc_flicker.py` | ADC のポリ抵抗（RIN、DAC1、基準電圧のフィルタ）のフリッカ雑音。PDK の式の ngspice での確認と、行動モデルのコード列を RTL の DWA に通した計算（11/12） |

入っているもの：

- 電源投入から：AVDD、DVDD、外付けの基準（1.9／1.4 V）が 1 ms で 0 から立ち上がる。すべての節点が 0 V から始まる（`uic`）。
- 基板（仮定、基板はまだない）：レギュレータの出力抵抗、10 µF と 100 nF（ESR／ESL 込み）、VCM の容量 10 nF／100 nF／1 µF。ボンディングワイヤは接続したパッド 1 個に 1 本（2 nH、0.1 Ω）。
- パッドリング：PDK の IO のネットリスト（asig_5p0 47 個、dvdd／dvss 各 8 個、コーナー 4 個）。
- チップの配線（`pex_chipnets.py`、穴埋めのあとのチップ、金属抵抗は typical）：接続した 13 個のアナログパッドのパッドセル（内部の Metal2、ESD ダイオード、容量）、AVDD／AVSS の網と 75 個のデカップリング、ブロックの間の配線（バイアス線、VCM、電極のストラップ、OUTP／OUTN、基準電圧）とその容量、切り替わる線との結合。ブロックはそれぞれ自分のピンで電源とグラウンドにつながる。afe_top の中の電源レール（端子からテールまで AVSS 0.746 Ω、AVDD 0.123 Ω）は見積もりで、一括の抵抗として入れた。
- 抽出したブロック：afe_top（素子と寄生容量、入力の信号経路の配線抵抗）、eeg_bias、eeg_ref。トリムはレジスタのリセット値（AFE_IBIAS code 2）で、`--ibias 3` のときはファームウェアが RESET_N の解除の 20 µs あとに AFE_IBIAS を 3 に書く。
- RTL の順序：RESET_N が low の間はチョッパが止まり、AFE_RST = 1。RESET_N の解除でチョッパが 128 kHz で動き出し、AFE_RST はソフトウェアが 5 ms で下ろす（モンテカルロでは解除をチョッパの任意の位相に置く）。デジタルの出力は DVSS と DVDD の間で振れる。
- ADC：入力抵抗（片側 18.75 kΩ）、基準の負荷（27.2 µA）、電源電流 4.7 mA を、それぞれ ADC のピンに置く（`e2e_startup.py` では ADC そのもの）。
- ばらつき：モンテカルロ（PDK の statistical：工程と素子ごとのばらつき。`.options seed` で再現できる）。MIM と poly 抵抗の素子ごとのばらつきは PDK にないので、仮の係数（MIM 1.41 %·µm、抵抗 3 %·µm）で入れた（抵抗の分は 10/28 に直した。下の雑音の節）。AVDD ±5 %。温度は 27 °C だけ（ユーザーの指定）。

残っている単純化：基板の値は仮定。ブロックの抽出は容量だけで、ブロックの中の抵抗は afe_top の電源レールの見積もりと入力の信号経路のほかはない。テストマルチプレクサは入れていない。デジタルブロックの電源電流とそのパッドはない（9 回目の通しの 1 つのチャンクに入れて確かめた。下の「デジタル側」の節）。MOS 容量は線形の代わり（`moscap_lin.spice`）。雑音は過渡では入れていない。

数値上の扱い（結果に効かないことを確かめた）：

- ボンディングワイヤの L に並列に 20 Ω（高周波の損失）を入れた。減衰がないと、最初のチョッパの切り替わりで ngspice が「Timestep too small」で止まる（500 Ω、2 kΩ でも後の切り替わりで止まる）。20 Ω と 100 Ω の差は、チョッパ周期の平均で 0.002 µV。
- 最大の時間刻みは 100 ns。10 ns との差は、チョッパ 10 周期の平均で 0.003 µV（1 µs では 0.14 µV）。

## チップの配線で分かったこと（10/27 夜）

- **バイアス回路と AFE のグラウンドがずれる。** eeg_bias は VBN を自分の AVSS に対して作るが、AFE のテールの AVSS はそれより 25.3 mV 高い（チップの配線で 13.7 mV、afe_top の中のレールで残り）。テールの VGS が 25 mV 小さくなり、AFE の電流は 18.3 mA になる（共通の理想グラウンドなら 22.6 mA、−19 %）。AFE_IBIAS の 1 段（code 2 → 3 で VBN +24.4 mV）とほぼ同じ大きさ。
- **電極のパッドセルの抵抗が抜けていた。** asig_5p0 の内部の Metal2 が 1 パッド 1.27 Ω、2 並列で電極 1 本あたり 0.636 Ω。10/24 以降の入力経路の配線抵抗（`pex_afe.RIN_EXTRACTED`）は、パッドの上の Metal5 からチョッパまでで、これを含んでいなかった（10/22 の予算 v1 では見込んでいた）。含めると片側 1.27／1.33 Ω、雑音 2.07 nVrms（それまで 1.48）。
- ADC での基準電圧は 478.6 mV（eeg_ref の出力で 489.6 mV、名目 493.1 mV）。eeg_ref から ADC までの配線（190〜200 Ω）に ADC の基準電流が流れる。
  - 10/29 に直した：この値は、ADC の基準の負荷を、C1 を半分にする前（10/23 まで）の 27.2 µA としたもの（`afe_startup.py` の `RADC` 18.4 kΩ）。DAC1 の素子の抵抗が 2 倍になった今の ADC は約 16 µA を引く。
  - トランジスタの ADC を入れた通し（`e2e_startup.py`、r6、変換の最初の 1 ms）では、ADC での基準電圧は 487.7 mV（eeg_ref の出力 494.0 mV、外の基準 500 mV、基準の電流 ±16.3 µA）。
  - ADC の DC の利得は、理想の 500 mV の基準に対して +2.9 %。そのうち 2.5 % が基準の降下（eeg_ref のフィルタで 1.2 %、チップの配線で 1.3 %）で、残りがループの利得（1.004）。一定の利得の誤差で、SNDR には効かない（DAC1 の基準電流は符号によらない、B3）。
  - AFE だけの結果（雑音、立ち上がり）はこの負荷にほとんどよらないので、回し直していない。`RADC` は 10/30 に今の ADC の値（29.9 kΩ）に直した。この値を使うのは 9 回目の配線で回した起動の結果から。
- 電源は AFE のテールで 3.210 V、バイアス回路で 3.244 V（レギュレータは 3.3 V）。AVDD の電流は 23.8 mA（ADC の 4.7 mA を含む）。

**11/9 の見直し：上の総残差は、パッドとストラップを二重に数えている。**

- 3.37 nVrms の内訳は次の 3 つ。
  - ADC 側 2.93 nVrms
  - ブランキングの折り返し 0.68 nVrms

- 上の表の AFE の値は、パッドセルとストラップの抵抗を電極と直列に含む（このスクリプトのチップの配線）。そのため、3 つ目の 1.5 nVrms は同じ抵抗をもう一度数えていた。
- これを除くと次のとおり（9 回目の配線、モンテカルロ 30 の平均。最悪のダイは、上の最悪の値から逆算した近い値）。

| 2 | 6.35 nVrms | 16.39 bit（約 16.36） |
| 3 | 6.13 nVrms | 16.44 bit（約 16.41） |

- ADC 側の 2.93 nVrms は、10/22 の予算の配分（歪み 2.0、チョッパ由来 1.5 などの枠）のままで、測った値ではない。
  - これまでに測った値で積み直すと約 1.54 nVrms になる。内訳は次のとおり。
    - ADC の抵抗：1.17（RIN 18.75 kΩ と DAC1 の 4kTR、利得 297.75 で換算）
    - OTA1：0.27（利得 297.75 で換算）
    - OTA1 のチョッパの折り返し：0.17
    - DAC1 の偶成分：0.47（行動モデル 123 dB）
    - AFE の HD3：0.64（帯域内のフルスケールで −120.3 dBc）

  - code 3 では合計 5.60 nVrms、16.57 bit になる。
  - これには ADC のポリ抵抗のフリッカ雑音が入っていない。PDK の大きさを今の電流でとると、フルスケールで 4.15 nVrms 加わり、16.26 bit になる（下の 11/12 の評価、図 33）。
  - 11/12 に直した。11/9 に積み直したときは、ADC の抵抗に RIN を 2 倍にする前の 0.91（利得 277）を使っていた（`eeg_adc.spice` の冒頭にあるとおり、RIN と DAC1 を 2 倍にして √2 倍になっている）。直す前は 1.35 nVrms、5.55 nVrms、16.58 bit と書いていた。
- 決め手は ADC 自身の歪みで、まだ確かめていない。
  - トランジスタのループの計算（8 ms）では、−110 dBc（2.1 nVrms）より下が見えていない。
  - PDK の抵抗のモデルは電圧係数が 0 なので、RIN と DAC1 のポリ抵抗の非線形は計算に入らない。
  - ADC の歪みが −110 dBc なら 16.47 bit、−120 dBc なら 16.56 bit（11/12 に上の直しで計算し直した。前は 16.49、16.57 bit）。16.5 bit には、約 −111.4 dBc より良い必要がある。
- **ポリ抵抗の雑音（11/12 の追記。後輩の Test-2-4 の検証で分かったことを、こちらでも確かめた）：**
  - ngspice で PDK の ppolyf_u_1k をそのまま使うと、本体の抵抗の式に v() があるため B 電源になり、熱雑音もフリッカ雑音も出ない。ADC の RIN の 1 単位（300 kΩ）で確かめると、雑音は 4kTR の 2.6 %（端子の抵抗の分だけ）だった（`res_typical`、m = 1 でも 16 でも同じ）。
  - 上の AFE の値（モンテカルロ）は、本体の式を定数にした `afe_startup.res_mm` を使うので、この問題はない。同じ 1 単位で、電流 0 では 4kTR と一致し、電流を流すとモデル表のフリッカ雑音 KF·|I|／(f·L·W)（KF 2.62e-26、AF 1、L と W は m）と 0.1 % 以内で一致した。
  - ADC の抵抗の熱雑音は 4kTR の手計算なので、これも問題ない。
  - ADC のポリ抵抗のフリッカ雑音は、それまでの予算に入っていなかった（後輩の報告書も未評価）。11/12 に評価した（下）。

**ADC のポリ抵抗のフリッカ雑音（11/12。`gf180/tapeout/pex/adc_flicker.py`、図 33 `documentation/figures/gf180/r10_20261109/viz/gf180_viz_r10_33_adc_poly_flicker.png`）**

- **PDK の式。** ppolyf_u_1k の本体は S_I = KF·|I|^AF／(f·L·W)（KF 2.62e-26、AF 1、L と W は実効の寸法で m）。
  - `res_mm`（ばらつきを切って typical）での ngspice の .noise と 0.06 % 以内で一致した（RIN の 1 単位、0.03〜3 µA）。
  - 0.41 µA の 1 単位で、10 Hz で 586 nV/√Hz になる。熱雑音は 70 nV/√Hz。
- **扱い方。** 抵抗のフリッカ雑音は抵抗値のゆらぎで、雑音電流は −I(t)·δR/R になる（Coram、McAndrew、Gullapalli、Kundert、"Flicker Noise Formulations in Compact Models"、IEEE TCAD 2020）。
  - 同じ論文は、PDK の |I|^AF の形を電流の向きが変わる使い方に当てはめると、直流のような 1/f が誤って出ることを示している。また、AF を 2 以外にする物理的な根拠はほとんどない、としている。
  - そこで予算には「モデル B」を使う。δR/R の大きさを PDK の式から電流 I_cal でとり、各抵抗のその時々の電流に掛ける。I_cal は DAC1 の列の電流 0.41 µA で、RIN のフルスケールの電流とも同じくらい。
  - PDK の式を瞬時の電流にそのまま当てはめる形（モデル A。PDK のモデルで周期的な雑音解析をするとこうなる）は、比べるためだけに載せる。
- **DAC1。** 抵抗は VREFP／VREFN につないだまま（ステアリング型）なので、各列にはコードによらず一定の 0.41 µA が同じ向きに流れる。11/12 の初めに「向きはフレームごとに変わる」と書いたのは誤りで、変わるのは行き先（OUTP か OUTN か）だけ。
  - PDK の式は、この直流の電流でそのまま使える。その雑音を、切り替えのスイッチが素子ごとに ±1 で振り分ける。
  - DWA（`eeg_dwa.sv`）では、各素子の選ばれ方の平均がコードに一致する。そのため、帯域内に残るのは信号に比例する分だけになる。
  - 行動モデルのコード列（`rtl/model/ct2_codes.py`、入力に 50 µVrms の白色雑音、4.1 s）を RTL と同じ DWA に通した。入力がないときは 0.03 nVrms だった。
  - サーモメータ（DWA_EN = 0）なら、入力がなくても 5.27 nVrms になる。DWA_EN のリセット値は 1 で、ファームウェアは変えないこと。
- **RIN。** 信号の電流が流れるので、これも信号に比例する。
- 合わせると、ADC の利得（RIN と DAC1 の比）の 1/f のゆらぎになる。外付けの基準電圧の雑音と同じ種類で、予算でもフルスケールで数える。

| 電極の入力（nVrms、0.5〜100 Hz） | RIN（B） | DAC1 | 計（B） | RIN（A） |
|---|---|---|---|---|
| なし（電極を短絡） | 0 | 0.03 | 0.03 | 0 |
| 直流 153 µV（オフセット DAC の残りの最大） | 0.84 | 0.43 | 0.94 | 2.18 |
| 正弦波 94 µV pk（フルスケールの 10 %） | 0.37 | 0.19 | 0.42 | 1.34 |
| 正弦波 943 µV pk（フルスケール、10 Hz） | 3.71 | 1.85 | 4.15 | 4.25 |

- **フルスケールの ENOB。** 5.60 nVrms に 4.15 nVrms を二乗和で足すと 6.97 nVrms で、16.26 bit になる。**16.5 bit に届かない。** モデル A では 4.63 nVrms、16.19 bit。
  - ただしこれは、PDK の式が 0.41 µA でも正しいとした場合。
  - AF = 1 なので、PDK の正規化した大きさ KF／I は電流が小さいほど大きくなる。これは抵抗の物理（大きさは電流によらない）と合わない。同じ抵抗を幅の方向に並列に分けると雑音が変わる形でもある。
  - PDK の文書は、1/f の測定条件を MOSFET についてしか書いていない（GF180MCU PDK の 2.3 節）。どの電流の範囲で合わせた式かは分からない。
  - PDK の式が 2.16 µA より上でしか成り立たず、それより下では大きさが一定なら、フルスケールでも 16.5 bit に届く（図 33 (b)）。どちらなのかは、測らないと決まらない。
- **EEG で普通の入力では影響は小さい。** フルスケールの 10 % 以下の信号、またはオフセットの残り 153 µV 以下なら 1 nVrms 以下で、総残差は 5.60 → 5.68 nVrms 以下にしかならない。
- **直す場合の候補（PDK の大きさを 0.41 µA でとった場合）。**
  - RIN と DAC1 の両方を ppolyf_u（350 Ω/sq、AF 1.79）にする。
    - 幅 1 µm の 1 本（857 µm）なら、雑音は 0.053 倍で 16.57 bit。同じ抵抗値で抵抗の面積は約 2.8 倍になる（RIN と DAC1 の本体は今 9,300 µm² と 36,100 µm²で、約 81,000 µm² 増える）。
    - ADC に収まる形として、幅 0.8 µm の 2 本を直列にする案を調べた（下の「RIN と DAC1 を ppolyf_u に替える案」）。雑音は 0.069 倍で、同じく 16.57 bit。
    - RIN／DAC1 の比を同じ種類の抵抗で保つため、両方を変える必要がある。
    - DAC1 の切り替えの節点の容量が増えるので、偶成分（今は −0.0014 fC）を確かめ直す必要がある（下の案で確かめた）。
  - ppolyf_u_1k のまま面積を 4 倍（582.56 × 2 µm）にする。0.50 倍で 16.48 bit。
  - どちらも ADC のレイアウトを作り直し、DRC／LVS、PEX、通しのシミュレーションをやり直すことになる。
- **チップで確かめる方法。** 電極に低雑音の直流（フルスケール近く）を入れ、入力が 0 のときと DATA の 1/f の床を比べる。
  - 床が直流に比例して上がれば、利得のゆらぎ。比例の係数から、実際の大きさが分かる。
  - オフセット DAC で直流を作ると、AVDD の雑音も同じ比で入る。外の直流源のほうがよい。
- **ほかの抵抗。**
  - 基準電圧のフィルタ抵抗 R_f（ppolyf_u、2 × 7 µm、30 µA）：VREFP − VREFN に 39 nVrms で、外付けの基準電圧に求める 375 nVrms の約 1/10。フルスケールで 0.052 nVrms。
  - バイアス、VCM の分圧、量子化器のはしご、R21：同相か、ループの中か、第 1 積分器のあとなので、無視できる。
  - RIN の同相の直流電流：9 回目の通しで、入力と仮想接地の同相の差は 0.06〜0.17 mV。単位あたり 1 nA 以下で、無視できる。
  - オフセット DAC の駆動抵抗：電流はチョッパの切り替えのあとに流れるだけで、半周期の中で落ち着くので効かない。

## VCM の容量と解除の時刻（基板とファームウェアへの要求）

VCM の外付け容量を大きくして、5 ms で解除した場合（typical）：

| VCM の容量 | 解除の時点の VCM | AFE |
|---|---|---|
| 10 nF | 1.650 V | 上の結果 |

## 電源、基準、バイアスの定常の動き（発振していないか）

図 26 の typical をシミュレータの計算点をすべて残して回し直し、解除後の 0.1〜0.4 ms（37 周期）で、電源、基準、バイアスの 20 節点を調べた（各節点の差を、チョッパ周期ごとに切って重ね、周期ごとに同じ部分と違う部分に分けた）。発振している節点はない。

- チョッパの切り替えのたびに 10〜50 ns の過渡がある（p-p：AFE のクロックドライバの電源 0.59 V、VCM − AVSS 144 mV、AFE の電源 108 mV、BLP 106 mV、VBCM 88 mV、バイアス回路の電源 53 mV、β マルチプライヤのゲート 51 mV、ADC の電源 45 mV、VBN 12 mV、VREFP − VREFN 1.6 mV）。どれも毎周期まったく同じ形で、一度逆向きに行き過ぎてから時定数約 0.5 µs（基板のレギュレータの出力抵抗 50 mΩ × 10 µF）で戻る。毎周期同じなので出力では一定のオフセットになるだけで、その分はシミュレーションした出力（上の −0.075 mV）に入っている。

## デジタル側：9 個のパッドとデジタルブロックの電源電流（11/8〜、`digital_noise.py`）

通し（`e2e_startup.py`）には、アナログのパッド、パッドリング、基板、ボンディングワイヤが入っている。一方で、デジタルブロックは電源電流を流さず、9 個のデジタルパッド（bi_24t）もない。デジタルの信号はどれも、リングの DVDDC と DVSSC の間の理想の源だった。

11/8 に、9 回目の配線の通しのチャンク 14 のデッキの写しに次のものを足した。チャンク 14 は 6.17 ms から始まり、AFE_RST の解除から 1.17 ms 後で、AFE と ADC が動いている。足したデッキを 47.3 µs（チョッパ 6 周期）回し、元のチャンクと比べた。スクリプトは `gf180/tapeout/pex/digital_noise.py`、結果は `gf180/tapeout/pex/runs/digital_noise/` にある（比べた値は `compare.json`）。デッキの ADC は 7 回目の抽出で、10 回目の抽出とはストラップのまわりだけが違う（ADC のループの節点は 0.03 fF 以下）。下の表と項目の値は、この 7 回目の抽出のデッキのもの（11/8〜9）。11/10〜11 に 10 回目の抽出で回し直し、同じ大きさの値になった（節の終わりの「10 回目の抽出での回し直し」）。図は 10 回目の図の 31（`documentation/figures/gf180/r10_20261109/viz/gf180_viz_r10_31_digital_noise.png`）で、11/11 から 10 回目の抽出の結果を描いている。

- **チップの DVDD／DVSS：** リングからブロックまでを星形でつないだ。抵抗は `supply_check.py`（r8／r9）の値で、デジタルブロック 0.19／1.12 Ω、DVDD と DVSS の間のデカップリング 0.67／1.50 Ω、ADC の DVDD／DVSS 4.32／1.41 Ω。
- **ブロック自身の VDD と VSS の間の容量：**
  - PDK のセルのネットリストを ngspice の AC で測った。eeg_digital_top 92 pF（うち fillcap 35 pF）、eeg_adc_dig 26 pF。
  - これに n ウェルの接合の見積もり（+25／+8 pF）を足し、直列抵抗は 0.5／1.5 Ω とした。
- **ブロックの電源電流：**
  - 元にしたのは、10/29 のゲートレベルの電力の計算（OpenSTA と VCD）。そこから MCLK のエッジごとの電荷を、フレームのサイクルごとに取り出した（`gf180/tapeout/digital/power/current_profile.py`）。
  - 取り出しには、liberty にあるフリップフロップのクロックのエネルギーの立ち上がりと立ち下がりへの分け方、クロック木の極性（どれも反転しないバッファ）、データの線の切り替わる容量を使った。
  - eeg_digital_top は 4.36 mA（立ち上がりのエッジで 77.7〜94.0 pC、立ち下がりで 54 pC）。eeg_adc_dig は 1.25 mA（立ち上がりで 20〜69.4 pC、立ち下がりで 14 pC）。
  - 1 つの電荷は幅 2 ns の三角形にし、デッキの出力のエッジの 2 ns 前から流した。
- **9 個の bi_24t：**
  - PDK のトランジスタのネットリストをリングに置いた。端子のつなぎ方は `chip_lay.DPAD` のとおり。
  - 基板とはボンディングワイヤ（2 nH、0.1 Ω、20 Ω）でつないだ。
  - MCLK は 3.3 V の発振器（エッジ 1.5 ns、33 Ω、配線 3 pF）から入れた。RESET_N と CS_N は high、SCLK と MOSI は low で、ホストから 33 Ω を通して与えた。
  - MISO、DRDY_N、RAW_DATA、RAW_CLK には、基板の 8 pF をつないだ。
- **ブロックが駆動する信号：** AFE とバイアスの制御とレジスタのビット、ADC のストローブと DAC の選択、コントローラ。どれも、駆動するブロックの電源の間で振れるようにした。

比べた組：

| 組 | 中身 |
|---|---|
| b1 | 普段の測定。MCLK が動き、ホストは止まり、RAW の出力は止まっている |
| b1iso | b1 と同じ源とパッドを、リングの別の写し（自分の電源を持ち、チップと共通のものがない）に置いた。シミュレータが受け取る事象は b1 と同じで、結合だけがない。b1 − b1iso が結合、b1iso − 元のチャンクがシミュレータの計算の差 |
| b2 | b1 に、ホストからの SPI の読み出しを足した（2 MHz、48 ビット、窓の 8〜34 µs） |
| b3 | b1 に、RAW の出力を足した（RAW_CLK = MCLK／4、RAW_DATA はランダム） |

電源と AFE の入力の揺れ（b1 と b3）：

| 場所 | 元のチャンク | b1 | b3（RAW の出力） |
|---|---|---|---|
| リングの DVDD／DVSS | 18／19 mV p-p | 59／57 mV p-p | 65／57 mV p-p |
| デジタルブロックの DVDD − DVSS | （なし） | 190 mV p-p、平均 −6.1 mV | 188 mV p-p、平均 −6.2 mV |
| ADC のデジタルの DVDD − DVSS | （なし） | 417 mV p-p、平均 −7.7 mV。フレームの最初の 4 サイクルで −240〜−360 mV | 415 mV p-p、平均 −7.7 mV |
| AFE の入力の同相 | | b1 − b1iso：7.2 mV p-p。MCLK のエッジごとに ±1 mV、フレームの最初で +4.6 mV | b3 − b1：15.2 mV p-p。RAW_CLK のエッジ（61 ns ごと）でとがる |
| AFE の入力の差動 | | b1 − b1iso：7.5 µV p-p（CHOP のエッジの直後 50 ns を除く） | b3 − b1：16.7 µV p-p（同じく除く） |

CHOP のエッジの直後 50 ns では、差動の差が最大 ±10 µV になる。ただし符号はエッジごとにばらばらで、2 本の計算の点が切り替わりの過渡の上でずれた分である。

AFE の出力のチョッパ周期ごとの平均を、5 周期で比べた。差は、一定のずれと、入力の 16 kHz の正弦（出力で 148.9 mV）の成分に分けた。正弦の周期ごとの平均は計算で正確に出せるので、それを基底にして当てはめた。

| 組 | 一定のずれ（電極換算） | 16 kHz の成分 | 残り | ADC の符号 |
|---|---|---|---|---|
| b1iso − 元のチャンク（計算の差） | +0.13 nV | 1.8 ppm | 0.04 nV rms | 48 フレームとも一致 |
| b1 − b1iso（結合） | +0.21 nV | 0.8 ppm | 0.08 nV rms | 48 フレームとも一致 |
| b2 − b1（SPI の読み出し） | −0.06 nV | 0.4 ppm | 0.17 nV rms | 48 フレームとも一致 |
| b3 − b1（RAW の出力） | −0.11 nV | 0.4 ppm | 0.11 nV rms | 48 フレームとも一致 |

b2 − b1 と b3 − b1 には、足した事象（SPI、RAW の出力）による計算の差も入っている。

- **結合の大きさ：** デジタル側の結合で AFE の出力にできる一定のずれは、電極換算で 0.21 nV。DATA の 1 LSB（0.19 nV）とほぼ同じで、シミュレータ自身の計算の差（0.13 nV）と同じ大きさ。周期ごとの差の大部分（最大 1.0 nV）は、16 kHz の正弦に対する ppm 単位の計算の差だった。
- **一定のずれにしかならない理由：** b1 では、チョッパ（MCLK／256）、フレーム（MCLK／32）、デジタルの電流がどれも MCLK に同期している。そのため結合は雑音にならない。0.2 nV は、雑音（総残差 6.3 nVrms、0.5〜100 Hz）や電極の DC オフセットと比べて無視できる。
- **SPI の読み出し：** ホストの SPI のクロックは MCLK と同期していないので、読み出しのたびにずれ方が変わる。それでも周期ごとの残りは 0.17 nV rms で、読み出し（26 µs）はサンプル周期（1 ms）の 2.6 % なので、無視できる。
- **小さなデッキでの切り分け（診断）：** 別に、リング、基板、デジタル側と簡単な負荷だけの小さなデッキを回した。電極のパッドの同相の揺れ（2.3 mV p-p）は MCLK のパッドのエッジから、リングとブロックの電源の揺れはコアの電流から来ていた。電流の三角形の幅を 1〜4 ns に変えると、リングの揺れは 71〜35 mV p-p になる。
- **b3（RAW の出力）：**
  - 最初の回しは 12.57 µs で「Timestep too small」で止まった（時間刻み 1.25e-17 s）。
  - 原因は区切り点の近さだった。RAW_CLK（PULSE）と RAW_DATA（PWL、時刻を 10 fs 刻みで書いた）の角が、チップのクロック（CMP、DCK、CHOP、BLK）と同じ格子に乗っていた。そのため、3 fs だけ離れた区切り点ができていた。
  - 2 本を同じ式から作った PWL にし、格子から 0.125 ns ずらした（コアの出力がパッドの A に着く時刻の違いとして、ありうる範囲）。デッキの近すぎる区切り点は、b1 と同じ浮動小数点の 1 ULP の差だけになった。これで 11/9 6 時 55 分に回し直し、21 時 4 分に 47.3 µs の最後まで回った（14.1 時間）。
  - 11/11 の訂正：このとき「b2 も 1 ULP の差だけ」としたのは誤りだった。b2 では MISO の角も格子の上にあり、ストローブの角と 3 fs だけ離れた組が 4 つあった。7 回目の抽出の b2 はそこを通ったが、10 回目の抽出の b2 はそこで止まった（下の「10 回目の抽出での回し直し」）。
  - RAW の出力で、リングの DVDD の揺れは 59 → 65 mV p-p になった。AFE の入力には RAW_CLK のエッジ（61 ns ごと）で鋭い揺れが足され、b3 − b1 は同相 15.2 mV p-p、差動 16.7 µV p-p（CHOP のエッジの直後を除く）。b1 の結合（7.2 mV、7.5 µV）の約 2 倍。
  - それでも AFE の出力では、一定のずれ −0.11 nV、周期ごとの残り 0.11 nV rms で、SPI の読み出し（0.17 nV rms）と同じ大きさ。ADC の符号は 48 フレームとも一致した。
  - RAW_CLK は MCLK を 4 で割ったものなので、周期ごとに変わるのは RAW_DATA の切り替わり（ここではランダム）だけ。残りの 0.11 nV rms（計算の差も含む）が周期ごとにばらばらの雑音だとしても、0.5〜100 Hz に入るのは約 0.005 nV rms で、総残差 6.3 nVrms と比べて無視できる。
  - 実際の RAW_DATA は変換の結果なので、入力によって変わる。ここでの差は全部で 0.2 nV 以下なので、入力によって変わる分もそれ以下。RAW の出力は試験用で、普段の測定では止まっている（RAW_EN = 0）。
  - 最初の回しで止まる前の 1 周期は −0.31 nV（RAW の角が格子の上）、回し直しの同じ周期は −0.01 nV。この差は、シミュレータ自身の周期ごとの差（b1iso − 元のチャンク、−0.6〜+1.0 nV）の範囲に入る。

**10 回目の抽出での回し直し（11/10〜11/11）：** ADC を 10 回目の抽出（`runs/adc_top_c_r10`）に差し替えて、5 本を回し直した（`digital_noise.py --adc r10`、結果は `runs/digital_noise_r10/`、比べた値は同じフォルダの `compare.json`）。

- 5 本は、元のチャンクにあたる A と、b1、b1iso、b2、b3。7 回目のときの A は通しのチャンクそのものだったが、今回は差し替えたデッキを同じ窓で回したものを A にした。
- デッキの違いは、ADC の抽出の 72 行（容量の値と、名前の変わった内側の節点 1 つ）と、その節点の初期値の名前だけ。ほかの行は 7 回目のデッキと同じであることを確かめた。
- A は 11/10 の 11 時 39 分に終わった。9 回目の通しのチャンク 14（ADC は 7 回目の抽出）と比べると、47 フレームの符号と DWA のポインタはすべて同じだった。ストローブでの差は、O2 が 1.4 µV 以内（O2 の振れは 34.1 mV）、O1 が 0.6 µV 以内、ADC の入力での AFE の出力が 0.29 µV 以内。
- b1iso、b1、b3 は、11/11 の 6 時 33 分、7 時 13 分、8 時 33 分に最後まで回った（22.3〜24.3 時間。9 回目の通しが終わるまでは効率コアだけで回した。下の「残り」）。
- b2 は 11/11 の 1 時 34 分に、22.83 µs で「Timestep too small」で止まった（時間刻み 1.25e-17 s、節点 bsel30）。
  - 原因は b3 の最初の回しと同じ、区切り点の近さだった。コアが出す MISO の PWL の角（時刻を 10 fs 刻みで書いた）が、ストローブ（VUCMP、PULSE）の角と 3 fs だけ離れていた。7 回目の抽出の b2 にも同じ組が 4 つあり、そのときはたまたま通っていた。
  - b3 と同じく、コアが出す MISO、MISO_OE、DRDY_N をチップのクロックの格子から 0.125 ns 遅らせた（`digital_noise.py` の `PAD_SKEW`、b3 と共通）。デッキの違いはこの 3 行だけ。
  - 0.1 ns より近い区切り点の組は、浮動小数点の ULP の差と、ホストの SPI のエッジ（MCLK と同期しない）と MCLK などの角の 16〜75 ps だけになった。後者は 7 回目の b2 も今回の b2 も通っている。
  - 1 時 37 分に回し直し、11 時 13 分に最後まで回った（9.6 時間）。止まった回しは `b2/*_stopped_ongrid.*` に残した。
  - 止まった回しとは、止まった 22.8 µs まで（チョッパ 2 周期、23 フレーム）で比べた。ADC の符号は 23 フレームとも同じで、周期ごとの差は電極換算で +0.27、+0.12 nV。これは b1 との差（+0.21、−0.12 nV）と同じ大きさで、0.125 ns ずらした影響は計算の差に埋もれている。リングの揺れは 0.01 mV 以内で同じだった。
  - 窓全体で見ると、リングの DVSS の揺れは 7 回目の b2（MISO が格子の上）の 58.7 mV p-p から 57.2 mV p-p になった。24.84 µs で MISO のエッジがクロックのエッジに重なっていた所の谷が、ずらしたことで −31.3 から −29.8 mV になった。

結果（AFE の出力のチョッパ周期ごとの平均を、上と同じように分けた。括弧は 7 回目の抽出の値）：

| 組 | 一定のずれ（電極換算） | 16 kHz の成分 | 残り | ADC の符号 |
|---|---|---|---|---|
| b1iso − A（計算の差） | +0.27 nV（+0.13） | 2.6 ppm（1.8） | 0.09 nV rms（0.04） | 48 フレームとも一致 |
| b1 − b1iso（結合） | +0.30 nV（+0.21） | 0.9 ppm（0.8） | 0.17 nV rms（0.08） | 48 フレームとも一致 |
| b2 − b1（SPI の読み出し） | +0.03 nV（−0.06） | 0.9 ppm（0.4） | 0.28 nV rms（0.17） | 48 フレームとも一致 |
| b3 − b1（RAW の出力） | −0.30 nV（−0.11） | 1.6 ppm（0.4） | 0.26 nV rms（0.11） | 48 フレームとも一致 |

- 5 本とも、48 フレームの ADC の符号は 7 回目の抽出のときと同じだった。
- 同じ組どうしで、ADC の抽出だけが違う 2 本（10 回目 − 7 回目）の周期ごとの差は、電極換算で b1iso が 0.07 nV 以内、b1、b2、b3 が 0.48 nV 以内。A は 0.66 nV 以内（7 回目の A は通しのチャンクそのもの）。
- 周期ごとの差は、計算の差（b1iso − A）が最大 1.66 nV（7 回目は 1.03 nV）で、ほかの組は 0.85 nV 以下。表の値が 7 回目より少し大きいのも、この計算の差の範囲に入る。
- 電源と AFE の入力の揺れ（上の表）は、表示の桁で同じだった（差動の b1 − b1iso だけ 7.5 → 7.6 µV p-p）。
- 結論は 7 回目の抽出のときと同じ。デジタル側の結合で AFE の出力にできる一定のずれは電極換算 0.30 nV（DATA の約 1.5 LSB）で、計算の差（0.27 nV）と同じ大きさ。MCLK に同期するので雑音にはならず、SPI の読み出しでも RAW の出力でも ADC の符号は変わらない。RAW の出力の残り 0.26 nV rms が周期ごとにばらばらの雑音だとしても、0.5〜100 Hz に入るのは約 0.01 nV rms で、総残差 6.3 nVrms と比べて無視できる。

入っていないもの（結果の読み方）：

- パッドリングは 1 つの節点（DVDDC／DVSSC）。東の MCLK のパッドから西の電極のパッドまでの、リングの抵抗とインダクタンスがない。そのため、MCLK から電極への結合は大きめに出ているはず。
- DVSS と AVSS の基板を通したつながり。
- ADC の量子化器のグラウンドは、抽出では AVSS で、eeg_adc の DVSS の端子は使われていない。11/9 に、これが名前の付け替えのせいではなかったと分かった。r9 までのレイアウトでは、量子化器の DVSS の端子がどこにもつながっておらず、抽出は基板を AVSS とするので AVSS に見えていた（`gf180_chip_assembly_20261023.md` の「組み直し（11/9、10 回目）」）。r10 ではこの端子を AVSS につないだので、レイアウトも抽出と同じ形になった。
- 活動は遅延のない計算から取ったので、グリッチは入っていない。電流はフレームのサイクルごとの平均で、符号によって変わる分は入っていない。
- 電荷の三角形の幅は仮定。1〜4 ns で揺れが約 2 倍変わる。
- typical だけ。ただし結合が MCLK に同期していることは角によらないので、一定のずれにしかならないという結論は変わらない。
