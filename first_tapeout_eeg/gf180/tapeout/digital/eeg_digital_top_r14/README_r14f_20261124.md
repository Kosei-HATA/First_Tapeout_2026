# r14 のマクロ（14 回目のチップ、11/24）

監査を経た r14 の RTL（`gf180/tapeout/rtl_r14/`、コミット e56bc9da。RTL の論理は 11/20 の監査の第 10 回から不変）を、外形 440 × 900 µm（11/19 のユーザーの判断）で LibreLane に通したランの記録。チップに入れたのは **r14f5_20261124**（`gf180/tapeout/layout/gds/r14/`、`install_r14_macro.sh`）。

## 設定

- `config.yaml`：r14m3（11/20 の試行）の設定（9 トラック、3.3 V の 9 コーナー、配置の密度 55 %、CTS のクラスタ 10 個／0.2 pF、配置後と GRT 後のタイミング修理の余裕 1.0／1.5 ns、GRT 後の設計規則の修理と slew の余裕 30 %）に、次を加えた。
  - `eeg_digital_top_r14.sdc`（PnR と signoff）：r13 のマクロの SDC（`../eeg_digital_top/eeg_digital_top.sdc`）と同じ制約に、リセットの例外を加えたもの。要件 VER-05 のとおり、フリップフロップのプリセットとクリアの弧（OpenSTA の `sta_preset_clear_arcs_enabled`）を有効にし、全ての OpenROAD の段（配置、CTS、タイミング修理、STA）で計時する。
    - RESET_N の主張（立ち下がり）からの経路は偽（RESET_N は全てのフリップフロップを非同期にリセットする。RST-01）。`set_false_path -from RESET_N` と、RESET_N が同期化器を通してリセットする全ての RN／SETN の立ち下がりを通る経路（`-fall_through`）。解除（立ち上がり）の recovery／removal は計時する。
    - SOFT_RESET（rst_n の立ち下がり）でクリア（セット）される制御の側のフリップフロップを通り、同じ rst_n で 5 MCLK 保持されるフリップフロップに終わる経路は偽。FIFO の記憶（リセットなしの 352 個。書いた所のみを読み、リセットで FIFO が空になる）に終わる経路も偽。ほかは全て計時する（時刻とデータの経路、CIC のクリア、rst_n と soft_cnt、出力の端子）。
    - フリップフロップは、端子 RESET_N、同期化器の Q、網 rst_n から緩衝器の木をたどって見つける（RTL の名前の残る網から）。
  - `sta_preset_clear.tcl`（`STA_EXTRA_CORNER_TCL_FILE`）：LibreLane の STA の段でも弧を有効にし、その旨をログに出す。
  - `CTS_DISTANCE_BETWEEN_BUFFERS: 150`：H ツリーに 150 µm ごとの緩衝器。これがないと、根の clkbuf_0_MCLK が 16 個の第 4 段の緩衝器を直接駆動し（0.61 pF、ファンアウト 16）、r14m3 の唯一の容量とファンアウトの警告となっていた。
- PDK（ciel 792ef670）と nix shell（`ws_gf180/eeg_padring`）は r13 のマクロと同じ。

## ラン（11/24）

| ラン | 設定（config.yaml に対して） | 結果 |
|---|---|---|
| r14f1 | 旧い SDC、クロックの長い配線の修理 250 µm、GRT 後の slew の余裕 50 % | GRT 後の設計規則の修理が 20 分を超えて進まず、止めた |
| r14f2 | 旧い SDC、H ツリーの緩衝器 150 µm、長い配線の修理 300 µm（配置後と GRT 後） | 完走。クロックの根の警告は解消。弧ありの旧い SDC では RESET_N 由来の偽の経路で −21.3 ns。新しい SDC で解き直すと、弧なしでも max_ss で −1.58 ns（a_sign → u_seq.timer）、slew の警告 6 個（4.67 ns） |
| r14f3 | 新しい SDC、H ツリー 150 µm、slew の余裕 40 %／40 % | GRT 後のタイミング修理のあとの詳細配置が失敗（DPL-0036、3 個） |
| r14f4 | 新しい SDC、クロックの長い配線の修理 250 µm、slew の余裕 40 %／40 % | 同じく失敗（18 個） |
| **r14f5** | 新しい SDC、H ツリー 150 µm | **完走。9 コーナーで setup ≥ ＋0.752 ns（max_ss）、hold ≥ ＋0.195 ns（min_ff）。slew、容量、ファンアウトの警告 0、配線の DRC、Magic DRC、KLayout DRC 0、LVS 一致、アンテナ 0、XOR 0** |
| r14f6 | r14f5 ＋ GRT 後のタイミング修理の余裕 0.5 ns、詳細配置の縦の移動の上限 300 µm | 完走。setup ＋0.134 ns（max_ss）で f5 に劣る |

- いずれも RTL の源（`rtl_r14/*.sv`、`rtl/eeg_chop1.sv`、`eeg_rnd_sat.sv`、`eeg_raw.sv`、`rtl/spec/*.svh`）の sha256 をランの前後に記録した（`runs/r14f*_src_{before,after}_20261124.txt`）。f3／f4 の後の記録には監査のセッションの作業中の変更（試験台、regmap.py）が git status に出るが、RTL と生成された svh の sha256 は前後で同じ。
